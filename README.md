# 🤖 Interview AI — Full Stack AI-Powered Interview Prep App

An AI-powered web application that analyzes your resume and a job description to generate a **personalized interview preparation plan**, including technical questions, behavioral questions, skill gap analysis, a day-by-day preparation roadmap, and a downloadable AI-tailored resume PDF.

## 🔍 How the App Works

1. **User signs up / logs in** — credentials are stored in MongoDB with hashed passwords. A JWT token is issued and stored in an HTTP cookie.
2. **User fills in the Home page** — they paste a job description, upload their resume PDF (max 3 MB), and optionally write a short self-description.
3. **Backend extracts the PDF text**, then sends all three inputs to **Google Gemini AI**.
4. **Gemini returns a structured JSON** report containing:
   - A **match score** (0–100) of the candidate vs. the job
   - **Technical questions** likely to be asked, with the interviewer's intention and a model answer
   - **Behavioral questions** with the same structure
   - **Skill gaps** with a severity rating (low / medium / high)
   - A **day-by-day preparation plan** with tasks
5. The report is **saved to MongoDB** and the user is navigated to their interview page.
6. On the Interview page the user can browse all sections via a sidebar nav, see their match score and skill gaps, and **download an AI-tailored resume PDF** (generated by Gemini + Puppeteer).

## 🖥 Backend — Step-by-Step Explanation

### 1. Entry Point — `server.js` (`Backend/server.js`)

```
require("dotenv").config()   // Load .env variables into process.env
const app = require("./src/app")
const connectToDB = require("./src/config/database")

connectToDB()                // Connect to MongoDB

app.listen(3000, () => {
    console.log("Server is running on port 3000")
})
```

This is the very first file Node.js runs. It:
- Loads environment variables (API keys, DB URI) from `.env`
- Imports the configured Express `app`
- Connects to MongoDB
- Starts listening on **port 3000**

---

### 2. App Setup — `src/app.js` (`Backend/src/app.js`)

This file creates and configures the Express application:

- **`express.json()`** — Parses incoming JSON request bodies so `req.body` works.
- **`cookie-parser`** — Parses cookies from incoming requests so `req.cookies.token` works (needed for JWT auth).
- **`cors`** — Enables Cross-Origin Resource Sharing, allowing the frontend (`http://localhost:5173`) to make API calls to the backend (`http://localhost:3000`). `credentials: true` is required so cookies are sent with cross-origin requests.
- Mounts the two routers:
  - `authRouter` at `/api/auth`
  - `interviewRouter` at `/api/interview`

---

### 3. Database Config — `src/config/database.js` (`Backend/src/config/database.js`)

```js
await mongoose.connect(process.env.MONGO_URI)
```

A simple async function that uses Mongoose to connect to MongoDB. The connection string is read from the `.env` file. If connection fails, the error is logged.

---

### 4. Models — `src/models/`

Mongoose models define the **shape of documents** stored in MongoDB collections.

#### `user.model.js` → Collection: `users`
| Field | Type | Rules |
|---|---|---|
| `username` | String | required, unique |
| `email` | String | required, unique |
| `password` | String | required (stored as bcrypt hash) |

#### `blacklist.model.js` → Collection: `blacklistTokens`
| Field | Type | Rules |
|---|---|---|
| `token` | String | required |
| `createdAt` | Date | auto (timestamps: true) |

When a user logs out, their JWT token is added here. Every protected request checks this collection to ensure the token hasn't been revoked — this is how **token invalidation** works without a session store.

#### `interviewReport.model.js` → Collection: `InterviewReport`

This is the most complex model. It stores the full AI-generated report.

| Field | Type | Description |
|---|---|---|
| `user` | ObjectId (ref: users) | Who owns this report |
| `title` | String | Job title extracted by AI |
| `jobDescription` | String | The raw job description |
| `resume` | String | Extracted text from the PDF |
| `selfDescription` | String | User-written blurb |
| `matchScore` | Number (0–100) | AI-calculated fit score |
| `technicalQuestions` | Array of sub-docs | `{ question, intention, answer }` |
| `behavioralQuestions` | Array of sub-docs | `{ question, intention, answer }` |
| `skillGaps` | Array of sub-docs | `{ skill, severity: low/medium/high }` |
| `preparationPlan` | Array of sub-docs | `{ day, focus, tasks[] }` |
| `createdAt / updatedAt` | Date | auto (timestamps: true) |

---

### 5. Middlewares — `src/middlewares/`

#### `auth.middleware.js` — JWT Authentication Guard

Used on every **private** route. It:
1. Reads the `token` from `req.cookies`
2. Checks if the token exists in the `blacklistTokens` collection (i.e. was the user logged out?)
3. Verifies the token with `jwt.verify()` using `process.env.JWT_SECRET`
4. If valid, attaches the decoded payload (`{ id, username }`) to `req.user` and calls `next()`
5. Returns `401 Unauthorized` if any check fails

#### `file.middleware.js` — Multer File Upload

Configures `multer` to:
- Store uploaded files **in memory** (`multer.memoryStorage()`) — no file is written to disk, the buffer is available as `req.file.buffer`
- Limit file size to **3 MB** (`3 * 1024 * 1024`)

---

### 6. Routes — `src/routes/`

#### `auth.routes.js` — mounted at `/api/auth`

| Method | Path | Access | Description |
|---|---|---|---|
| `POST` | `/api/auth/register` | Public | Create new account |
| `POST` | `/api/auth/login` | Public | Log in with email + password |
| `GET` | `/api/auth/logout` | Public | Clear cookie + blacklist token |
| `GET` | `/api/auth/get-me` | 🔒 Private | Get currently logged-in user |

#### `interview.routes.js` — mounted at `/api/interview`

| Method | Path | Access | Description |
|---|---|---|---|
| `POST` | `/api/interview/` | 🔒 Private | Generate a new interview report (multipart form with resume PDF) |
| `GET` | `/api/interview/` | 🔒 Private | Get all reports for logged-in user (lightweight, no heavy fields) |
| `GET` | `/api/interview/report/:interviewId` | 🔒 Private | Get a single full report by ID |
| `POST` | `/api/interview/resume/pdf/:interviewReportId` | 🔒 Private | Generate and download a tailored resume PDF |

Every interview route is protected by `authMiddleware.authUser`. The report generation route also passes through the `upload.single("resume")` file middleware.

---

### 7. Controllers — `src/controllers/`

Controllers are the **request handlers** — they receive `req` and `res`, orchestrate the logic, and return the HTTP response.

#### `auth.controller.js`

- **`registerUserController`** — Validates inputs, checks for duplicate username/email, hashes the password with `bcrypt` (10 salt rounds), creates the user, signs a JWT, sets it as a cookie, responds with user data.
- **`loginUserController`** — Finds user by email, compares password with `bcrypt.compare`, signs a new JWT, sets cookie, responds.
- **`logoutUserController`** — Reads cookie token, adds it to the blacklist, clears the cookie.
- **`getMeController`** — Uses `req.user.id` (set by auth middleware) to fetch and return user data from DB.

#### `interview.controller.js`

- **`generateInterViewReportController`** — Extracts text from the uploaded PDF buffer using `pdf-parse`, calls `generateInterviewReport()` from the AI service, saves the result to MongoDB, returns the report.
- **`getInterviewReportByIdController`** — Finds a report by `_id` AND `user` (security: you can only view your own reports).
- **`getAllInterviewReportsController`** — Returns all reports for the user, sorted newest first, with heavy fields (resume text, questions, etc.) excluded using `.select()` for a lightweight list view.
- **`generateResumePdfController`** — Fetches the report by ID, calls `generateResumePdf()` from the AI service, and streams the PDF buffer back as `application/pdf` with a `Content-Disposition: attachment` header to trigger a browser download.

---

### 8. Services — `src/services/`

#### `ai.service.js` — The Brain of the App

This file contains all AI and PDF generation logic.

**Google Gemini Setup:**
```js
const ai = new GoogleGenAI({ apiKey: process.env.GOOGLE_GENAI_API_KEY })
```

**`generateInterviewReport({ resume, selfDescription, jobDescription })`**

1. Defines a **Zod schema** describing the exact JSON shape Gemini must return (matchScore, technicalQuestions, behavioralQuestions, skillGaps, preparationPlan, title).
2. Converts the Zod schema to JSON Schema using `zodToJsonSchema` and passes it to Gemini's `responseSchema` config — this **forces structured output**.
3. Sends a prompt to `gemini-3-flash-preview` with `responseMimeType: "application/json"`.
4. Parses and returns the JSON response.

**`generateResumePdf({ resume, selfDescription, jobDescription })`**

1. Defines a Zod schema requiring a single `html` field.
2. Asks Gemini to generate a **professional, ATS-friendly, tailored HTML resume** based on the user's inputs and job description.
3. Passes the generated HTML to `generatePdfFromHtml()`.

**`generatePdfFromHtml(htmlContent)`**

1. Launches a **headless Chromium browser** with Puppeteer.
2. Opens a new page and sets the AI-generated HTML as the content.
3. Exports the page as a PDF (A4 format, 20mm margins).
4. Closes the browser and returns the PDF buffer.

## 🌐 Frontend — Step-by-Step Explanation

### 1. Entry Point — `main.jsx` + `App.jsx` (`Frontend/src/`)

`main.jsx` is the standard Vite/React entry: it mounts `<App />` into the `#root` div in `index.html`.

`App.jsx` wraps everything with two React Context providers and the router:

```jsx
<AuthProvider>         {/* Provides user state globally */}
  <InterviewProvider>  {/* Provides report state globally */}
    <RouterProvider router={router} />
  </InterviewProvider>
</AuthProvider>
```

---

### 2. Routing — `app.routes.jsx` (`Frontend/src/app.routes.jsx`)

Uses **React Router v7**'s `createBrowserRouter`:

| Path | Component | Protected? | Description |
|---|---|---|---|
| `/login` | `Login` | ❌ Public | Login form |
| `/register` | `Register` | ❌ Public | Register form |
| `/` | `Home` | ✅ Private | Generate new report + list past reports |
| `/interview/:interviewId` | `Interview` | ✅ Private | View a specific report |

The `Protected` component wraps private routes. It checks the auth state and redirects to `/login` if the user is not authenticated.

---

### 3. Auth Feature — `src/features/auth/`

This feature is organized into 4 layers:

#### `auth.context.jsx` — Global State
Creates a React Context holding `user`, `setUser`, `loading`, `setLoading`. Wraps the whole app so any component can access auth state.

#### `services/auth.api.js` — API Layer
Creates an Axios instance with:
- `baseURL: "http://localhost:3000"` — all calls go to the backend
- `withCredentials: true` — sends the JWT cookie with every request

Exports 4 functions: `register`, `login`, `logout`, `getMe` — each makes the corresponding API call.

#### `hooks/useAuth.js` — Logic Layer
Consumes the `AuthContext` and wraps the API calls with state management:
- `handleLogin` / `handleRegister` / `handleLogout` — call the API, then update `user` state
- On mount (`useEffect`), calls `getMe()` to **auto-restore the session** from the cookie if the user refreshes the page

#### `components/Protected.jsx` — Route Guard
```jsx
if (loading) return <h1>Loading...</h1>  // Wait for session restore
if (!user) return <Navigate to="/login" /> // Not logged in → redirect
return children                            // Logged in → render the page
```

#### `pages/Login.jsx` & `pages/Register.jsx`
Standard form pages that call `handleLogin` / `handleRegister` from `useAuth`.

---

### 4. Interview Feature — `src/features/interview/`

#### `interview.context.jsx` — Global State
Holds `loading`, `report` (single report), `reports` (list of all reports).

#### `services/interview.api.js` — API Layer
Axios calls to the interview endpoints:
- `generateInterviewReport` — sends a `FormData` object (`multipart/form-data`) with the job description, self description, and resume file
- `getInterviewReportById` — GET by ID
- `getAllInterviewReports` — GET all
- `generateResumePdf` — POST, sets `responseType: "blob"` to receive binary PDF data

#### `hooks/useInterview.js` — Logic Layer
Wraps all API calls with state management. Also:
- Auto-fetches the correct data on mount: if `interviewId` param exists → fetch single report; otherwise → fetch all reports
- `getResumePdf` creates a temporary object URL from the blob and programmatically clicks a hidden `<a>` tag to trigger a file download

#### `pages/Home.jsx` — Input Page
- Textarea for job description (max 5000 chars)
- File dropzone for resume PDF
- Textarea for self description (alternative to resume)
- On submit: calls `generateReport()`, waits for the response, navigates to `/interview/:id`
- Below the form: a list of recent reports with match score badges

#### `pages/Interview.jsx` — Report Viewer Page
- **Left sidebar nav** — 3 sections: Technical Questions, Behavioral Questions, Road Map
- **Main content** — renders the active section:
  - Questions use a collapsible `QuestionCard` component (click to expand intention + model answer)
  - Roadmap uses a `RoadMapDay` component (day badge, focus title, task list)
- **Right sidebar** — Match Score ring (color-coded: green ≥80, yellow ≥60, red <60) + Skill Gap tags (color-coded by severity)
- **Download Resume button** — calls `getResumePdf()` from the hook

## 🔐 Environment Variables

Create a `.env` file inside the `Backend/` folder:

```env
GOOGLE_GENAI_API_KEY=your_google_gemini_api_key_here
MONGO_URI=mongodb://localhost:27017/interview-ai
JWT_SECRET=your_super_secret_jwt_key_here
```

> ⚠️ **Note:** The current `.env` is missing `JWT_SECRET`. You must add it — it's used to sign and verify JWT tokens. Without it, auth will fail with an error.

- **`GOOGLE_GENAI_API_KEY`** — Get from [Google AI Studio](https://aistudio.google.com/). Required for Gemini AI calls.
- **`MONGO_URI`** — MongoDB connection string. `mongodb://localhost:27017/interview-ai` works if you have MongoDB installed locally.
- **`JWT_SECRET`** — Any long, random string (e.g., `openssl rand -hex 32`). Keep it secret.

## 🔄 Data Flow Walkthrough

Here is the complete journey of a request when a user generates an interview report:

```
User fills Home form and clicks "Generate My Interview Strategy"
        │
        ▼
[Frontend] Home.jsx
  └─ handleGenerateReport() called
  └─ Calls useInterview().generateReport({ jobDescription, selfDescription, resumeFile })
        │
        ▼
[Frontend] useInterview.js
  └─ Calls generateInterviewReport() from interview.api.js
        │
        ▼
[Frontend] interview.api.js
  └─ Axios POST to http://localhost:3000/api/interview/
  └─ FormData: { resume (PDF file), jobDescription, selfDescription }
  └─ Cookie with JWT is automatically sent
        │
        ▼
[Backend] Express receives POST /api/interview/
  └─ authMiddleware.authUser runs
      ├─ Reads token from cookie
      ├─ Checks it's not blacklisted
      ├─ Verifies JWT → attaches req.user = { id, username }
      └─ Calls next()
  └─ upload.single("resume") runs
      └─ Multer stores file buffer in req.file.buffer
        │
        ▼
[Backend] interview.controller.js → generateInterViewReportController()
  └─ pdf-parse extracts text from req.file.buffer
  └─ Calls ai.service.js → generateInterviewReport()
        │
        ▼
[Backend] ai.service.js → generateInterviewReport()
  └─ Builds prompt with resume + selfDescription + jobDescription
  └─ Calls Gemini API (gemini-3-flash-preview) with responseSchema (Zod → JSON Schema)
  └─ Gemini returns structured JSON
  └─ JSON.parse(response.text) → returns the report object
        │
        ▼
[Backend] interview.controller.js (continued)
  └─ interviewReportModel.create({ user: req.user.id, ...aiReport })
  └─ Saves full report to MongoDB
  └─ res.status(201).json({ interviewReport })
        │
        ▼
[Frontend] useInterview.js
  └─ setReport(response.interviewReport)
  └─ Returns the report to Home.jsx
        │
        ▼
[Frontend] Home.jsx
  └─ navigate(`/interview/${data._id}`)
```
